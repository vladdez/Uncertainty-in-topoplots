Open-ended feedback

Participants included in the qualitative content analysis: 70.

Meaning units extracted: 277 unique units, coded to visualizations in 291 rows. 12 units evaluate more than one visualization (for example, one statement that several named plots were easy to interpret) and therefore appear once per visualization they evaluate.

Participant comments are presented in two groups. Select an Expand button to read the responses.

Qualitative content analysis

ID links every unit to its original A305 response; it is the participant ID used on all pages. The downloadable workbook identifies participants by the survey’s record number (CASE), which does not change between data exports. Participant wording is retained as closely as possible; themes and intensities are interpretive codes. Use the search box or column filters to explore the table.

References to bivariate plots without an identified variant are coded as General bivariates; a unit is coded to both Bivariate corner and Bivariate range only when the response names both variants (IDs 74 and 102). Proposed redesigns are included only when they express an evaluation of the displayed visualization; suggestions alone are not assigned an intensity.

WarningCoding is not yet validated

The units were coded by large language models with one fixed prompt (data/a305_content_analysis_prompt.md): GPT-5.6 Sol (via Codex) coded the first responses and Claude coded the responses of later participants (IDs 115 and above) and checked all codes against the coding rules. No human coder has checked the codes yet, so the themes and intensities below are provisional. A random subsample is prepared for a human second coder (see Inter-coder agreement).

The coders used the neutral code 0 for only 3 of 277 units, so the intensity scale is in practice a four-point negative/positive scale.

Coded meaning units

Evaluation intensity by theme and visualization type

This descriptive analysis gives each participant at most one value within each visualization–theme combination. It therefore avoids treating multiple meaning units from the same participant as independent observations. Comments coded as General bivariates are retained in the original dataset but excluded here because they do not identify one of the seven visualization types.

A unit that evaluates several visualizations (12 units) counts once in each of those visualizations, because it is an evaluation of each, but it is never counted twice within one visualization. Comparisons across visualizations are therefore not independent where a participant evaluated several visualizations in one statement.

Cells with only one or two participants are shown as faded points without a box in the figure, and without a median or mean in the table. They are too sparse to summarise.

make_a305_intensity_figure <- function(
  plot_data,
  fade_sparse = FALSE
) {
  # One fixed visualization order in every panel (the display order of every
  # figure, audit V1), with empty slots kept, so the columns line up across
  # panels (Wilke ch. 21; audit V4).
  visualization_limits <- levels(plot_data$visualization)

  theme_panel_counts <- plot_data |>
    count(theme, name = "n_entries") |>
    arrange(desc(n_entries), theme)

  theme_panel_order <- theme_panel_counts$theme
  theme_panel_labels <- setNames(
    paste0(
      theme_panel_counts$theme,
      " (N = ",
      theme_panel_counts$n_entries,
      ")"
    ),
    theme_panel_counts$theme
  )

  plot_data <- plot_data |>
    group_by(theme, visualization) |>
    mutate(
      n_group = n(),
      point_alpha = if_else(
        fade_sparse & n_group <= a305_sparse_max_n, 0.25, 0.8
      )
    ) |>
    ungroup() |>
    mutate(theme = factor(theme, levels = theme_panel_order))

  # Median tick per cell (audit V11: no boxes for 3-10 values on a 5-point
  # code); sparse cells get no tick, as they get no median in the table.
  median_data <- plot_data |>
    group_by(theme, visualization) |>
    summarise(
      median_intensity = median(median_intensity),
      n_group = n(),
      .groups = "drop"
    ) |>
    filter(!fade_sparse | n_group > a305_sparse_max_n)

  # Horizontal labels; slightly smaller when there are eight columns. (21 rather
  # than 24 with seven columns, so "Confidence intervals" and "Uncertainty
  # markers" keep a gap between them.)
  x_axis_text <- ggtext::element_markdown(
    size = if (length(visualization_limits) > 7) 19 else 21,
    # showtext draws line gaps 180/96 times too wide (see the caption below), so
    # 0.5 gives normal spacing between the two lines of a label.
    lineheight = 0.5,
    margin = margin(t = 6)
  )

  ggplot(
    plot_data,
    aes(
      x = visualization,
      y = median_intensity,
      colour = visualization == "Basic",
      fill = visualization == "Basic"
    )
  ) +
    geom_hline(yintercept = 0, linetype = "dashed", linewidth = 0.5, colour = "#9E9E9E") +
    geom_errorbar(
      data = median_data,
      aes(ymin = median_intensity, ymax = median_intensity),
      width = 0.62,
      linewidth = 1.4
    ) +
    ggbeeswarm::geom_beeswarm(
      aes(alpha = point_alpha),
      size = 2.4,
      cex = 1.15,
      priority = "ascending",
      corral = "gutter",
      corral.width = 0.5
    ) +
    facet_wrap(
      vars(theme),
      scales = "fixed",
      axes = "all_x",
      ncol = 2,
      labeller = as_labeller(theme_panel_labels)
    ) +
    scale_x_discrete(
      limits = visualization_limits,
      labels = visualization_axis_labels,
      drop = FALSE
    ) +
    scale_colour_manual(
      values = c(`FALSE` = "#333333", `TRUE` = basic_accent),
      guide = "none"
    ) +
    scale_fill_manual(
      values = c(`FALSE` = "#D9D9D9", `TRUE` = basic_accent_fill),
      guide = "none"
    ) +
    scale_alpha_identity() +
    scale_y_continuous(
      limits = c(-2.15, 2.15),
      breaks = -2:2,
      labels = intensity_axis_labels,
      minor_breaks = NULL
    ) +
    labs(
      x = NULL,
      y = "Participant-level median evaluation intensity",
      # Two lines, so the caption can use a legible size (audit V2).
      caption = paste0(
        "Points represent participants, not individual meaning units. ",
        "Panel N is the number of plotted participant-visualization entries.\n",
        if (fade_sparse) {
          paste0(
            "Horizontal tick: median. Faded points without a tick: cells with ",
            a305_sparse_max_n, " or fewer participants. "
          )
        },
        "-2 = strongly negative; +2 = strongly positive."
      )
    ) +
    # Sizes balanced at the ~1100 px display width of this 15-in figure (audit
    # V2): y tick labels and caption close to the x labels, panel and axis
    # titles one step larger rather than twice as large.
    plot_theme(base_size = 18) +
    theme(
      strip.text = element_text(face = "bold", size = 28),
      # Light strips (audit V11): the panel titles, not their boxes, carry weight.
      strip.background = element_rect(fill = "#F2F2F2", colour = NA),
      axis.text.x = x_axis_text,
      axis.text.y = element_text(size = 22),
      axis.title.y = element_text(size = 28),
      axis.ticks.x = element_blank(),
      panel.spacing = grid::unit(1.2, "lines"),
      # lineheight 0.6: showtext draws line gaps 180/96 times too wide, so this
      # gives about 1.1 lines.
      plot.caption = element_text(
        hjust = 0.5, face = "italic", size = 26, lineheight = 0.6,
        margin = margin(t = 12)
      )
    )
}

Participant-based summary

Sample sizes count unique participants. Medians and means are calculated from the participant-level medians shown in the figure, not directly from meaning units. 39 of 68 theme × visualization cells have 2 or fewer participants; their median and mean are left blank (shown as “n ≤ 2”). Means are rounded to one decimal, as they average a five-point code.

Inter-coder agreement

A reproducible random sample of 63 of 277 unique meaning units (23%, stratified by visualization) is prepared for a human second coder in data/a305_double_coding_sample.csv (not published: it contains the full responses). The file shows each unit and its full response, but not the first coder’s codes. The second coder codes the first coder’s segmentation, so agreement on unit boundaries is not assessed.

Status: not yet coded. Once the file is filled in, the table below reports percent agreement and Cohen’s kappa for the visualization, theme (unweighted) and intensity (quadratic-weighted) codes.

Summary of the open-ended feedback

  • Data. Visualization comments from 70 of 150 participants were coded. They gave 277 meaning units; 12 units evaluate more than one visualization.
  • Main themes. The most common themes were Interpretability (59 participant entries), Preference (27 participant entries), and Aesthetics (26 participant entries), out of 13 themes.
  • Mostly positive (at least two thirds of the non-neutral participant entries positive): Adjacent plots (29 positive, 4 negative), Confidence intervals (22 positive, 4 negative), and Basic topoplot (12 positive, 5 negative).
  • Mixed: Bivariate range (16 positive, 10 negative), Animation (16 positive, 20 negative), and Uncertainty markers (20 positive, 30 negative).
  • Mostly negative: Bivariate corner (10 positive, 28 negative).
  • Most frequent negative cells (at least five participants): aesthetics of Uncertainty markers (14 participants, median -1), interpretability of Animation (13 participants, median -1), interpretability of Bivariate corner (11 participants, median -2), and medium compatibility of Animation (11 participants, median -1).
  • Most frequent positive cells (at least five participants): interpretability of Confidence intervals (8 participants, median +1.5), interpretability of Adjacent plots (7 participants, median +2), preference of Adjacent plots (7 participants, median +2), and preference of Confidence intervals (6 participants, median +2).
  • Caveat: coding not yet validated. The codes come from language models and no human coder has checked them; the human second coding is not done yet. The neutral code was used for only 3 of 277 units.
  • Interpretation. These are descriptive counts from the participants who chose to comment, and one participant can contribute to several visualizations. They show which aspects participants mentioned and in which direction, not which visualization works better, and they stay provisional until the coding is checked.

basic topological and confidence interval visualizations because they were relatively intuitive and

the signal and its uncertainty separately could be a more effective approach. They allow researchers

evaluate these approaches not only in terms of interpretation accuracy and response time but also
perceived cognitive workload, visual search efficiency, and user preference. It may also be valuable
to investigate whether visualization preferences differ between experienced EEG researchers and
beginners. Overall, the study addresses an important issue in scientific visualization: how to
communicate statistical uncertainty while maintaining perceptual clarity and supporting reliable
interpretation.

feedback_to_pdf <- function(df, title, filename) {

  df <- df %>%
    filter(!is.na(feedback), feedback != "") %>%
    arrange(ID)

  comments <- paste0(
    "<section class='comment'>",
    "<div class='id'>ID: ",
    htmltools::htmlEscape(as.character(df$ID)),
    "</div>",
    "<div class='text'>",
    htmltools::htmlEscape(df$feedback),
    "</div>",
    "</section>"
  )

  html <- paste0(
    "<!DOCTYPE html>
    <html>
    <head>
    <meta charset='UTF-8'>
    <style>
      @page {
        size: A4;
        margin: 18mm;
      }

      body {
        font-family: Arial, sans-serif;
        font-size: 11pt;
        line-height: 1.45;
        color: #222;
      }

      h1 {
        font-size: 18pt;
        margin-bottom: 20px;
      }

      .comment {
        padding: 10px 0 14px 0;
        border-bottom: 1px solid #cccccc;
        page-break-inside: avoid;
      }

      .id {
        font-weight: bold;
        margin-bottom: 5px;
      }

      .text {
        white-space: pre-wrap;
        overflow-wrap: anywhere;
      }
    </style>
    </head>

    <body>
      <h1>", htmltools::htmlEscape(title), "</h1>",
      paste(comments, collapse = "\n"),
    "</body>
    </html>"
  )

  html_file <- tempfile(fileext = ".html")
  writeLines(html, html_file, useBytes = TRUE)

  output_file <- normalizePath(filename, mustWork = FALSE)

  pagedown::chrome_print(
    input = html_file,
    output = output_file
  )

  message("Saved to: ", output_file)
}
