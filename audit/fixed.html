F31. Feedback codes were linked by row position

formerly A3 → F31

Severity: Moderate · Area: Open-ended feedback, data preparation

Problem. The participant ID on the pages is only a row number after the sample filters (1, 2, 3, …). The A305 coding workbook was filed under this number. If a new export were sorted or filtered differently, every code after the change would silently move to the wrong participant. A check after each refresh caught this, but the design itself was fragile.

Resolution (24 Nov 2026). The workbook is now keyed on SoSci Survey’s record number (CASE), which a participant keeps in every export.

  • Analysis data. scripts/analysis_setup.R keeps CASE (and checks that it is unique); before, it was dropped with the first columns.
  • Migration. scripts/migrate_a305_to_case.R replaced the ID column of the workbook (291 rows, 70 participants) and of data/a305_excluded_ids.csv (5 rows) with CASE. All other cells are unchanged, and converting back gives the original IDs. The workbook’s Excel table now also covers the rows appended after it was created.
  • Feedback page. It looks up each participant’s ID from CASE, so the page still shows the same IDs as all other pages. Its numbers and tables are unchanged.
  • Refresh tools. scripts/check_data_refresh.R, the append-script template (scripts/append_a305_ids_150_150.R) and the data-refresh instructions now use CASE; older append scripts are marked historical. The check still confirms that every coded unit occurs in its participant’s response (291 of 291).
  • Public workbook. The download now shows CASE instead of ID. CASE was already in the published de-identified data, so nothing new is disclosed.

F30. Cache and duplicate-filter hazards

formerly U22 → F30

Severity: Low · Area: pages/subjective.qmd (setup); scripts/prepare_task2_region_plot_data.R

Problem. Two places could silently go out of date.

  • Stale cache. Quarto saves the results of slow code chunks and reuses them on the next render if their inputs look unchanged. The Subjective page’s cached sensitivity analysis (ratings without the flagged participants) reads the flag rules in scripts/data_quality.R, but the cache did not watch that file. Changing a rule would have updated the Sample page and left the Subjective result stale.
  • Second sample definition. The Task 2 plotting-prep script read the survey export itself and copied the “who is in the sample” filters, so the two definitions could drift apart.

Resolution (24 Nov 2026).

  • Cache. The Subjective page now passes scripts/data_quality.R to configure_analysis_cache(), so editing the flag rules invalidates its cache.
  • Sample definition. The prep script now sources scripts/analysis_setup.R and uses its analytic sample (data). Its output is unchanged: 3,129 responses and 1,344 plot rows, identical to the previous version.

F29. Rating models: test ignored clustering; estimates were conditional

formerly U21 → F29

Severity: Low · Area: pages/subjective.qmd (model checks, rating tables and figures); pages/figures.qmd

Problem.

  • The proportional-odds test ignored clustering. Each participant rated all seven visualizations, so their seven ratings are related. The test used a model without a participant term (clm) and treated them as independent, which makes p values too small.
  • The estimates were for a typical participant (participant effect at zero), not averages over all participants, but were labelled “model-smoothed mean ratings”.

Resolution (24 Nov 2026).

  • Test. It now uses clmm2 with a participant random intercept, comparing the model with and without visualization-specific thresholds. (clmm cannot fit the second model: it ignores the nominal argument with a warning.) The conclusion is unchanged: proportional odds is rejected for all four items.
  • Labels. Tables, figure captions, the contrast-figure axis and the Figures-page alt texts now say “expected rating, typical participant”. These values stay within 0.08 scale points of the raw means.
Item Old test (clm) New test (clmm2, participant random intercept)
Helpful for comparison LR 36.2, p = .007 LR 33.6, p = .014
Helpful for detection and integration LR 49.4, p < .001 LR 48.9, p < .001
Would use in publication or presentation LR 38.3, p = .004 LR 39.1, p = .003
Aesthetically appealing LR 50.5, p < .001 LR 51.7, p < .001

All tests have 18 degrees of freedom (measured 24 Nov 2026, N = 150).

F28. Unguarded prose, stale labels, typos

formerly U23 → F28

Severity: Low · Area: Task 1, Task 2, Time pages

Problem. Several small things on the public pages were wrong or could silently become wrong: a sentence that claimed no missing data without checking it, a figure with an old title and an order that did not match what it showed, three typos, and a Time page that used a different adjustment and different degrees of freedom than it said.

Resolution (23 Nov 2026).

  • Task 1, “no responses excluded”. A stopifnot() now stops the render if task1_trials.R ever drops a row, so the sentence cannot become false unnoticed.
  • Task 2 gradient figure (also figures/task2_gradient_figure.png). The in-figure title “Detection task accuracy” is removed (the caption describes the figure, as in the Wilke rule on one title per figure), and the rows are ordered by the mean the figure shows instead of the median (part of V9).
  • Typos. “becausewe” → “because we” (Task 1); “participan” → “participant” (Task 2); “This calcaulation is actually more complicated.” rewritten as: “The region score is the mean |voltage| / SE in that region, rescaled within each stimulus so that the weakest region scores 0 and the strongest 1. The steps are in the note below.”
  • Time page, adjustment. dunnettx (an approximation) is replaced by mvt, the exact multivariate-t Dunnett adjustment used on the other pages.
  • Time page, degrees of freedom. All time models now use asymptotic degrees of freedom (lmer.df = "asymptotic"), as the model note says. Before, the 1.5 × IQR sensitivity fit had fewer than 3,000 trials, so emmeans silently switched to Kenward–Roger.

Effect. The main time results are unchanged. One sensitivity comparison sits on the edge: Task 1 Uncertainty markers vs Basic topoplot under the 1.5 × IQR rule.

  • 23 Nov 2026, N = 149: with the same degrees of freedom as the other fits, it became “slower”, so all three outlier rules agreed.
  • 24 Nov 2026, N = 150: after the data refresh it is again “not clearly different” (time ratio 1.09 [0.99, 1.19]), while the cap (1.12 [1.01, 1.24]) and all trials (1.14 [1.02, 1.27]) say “slower”. The Time page reports this one change.

The interval only just touches 1, so this verdict can flip with small changes in the data; it does not change the main conclusion that all six visualizations took longer than Basic topoplot.

F24. Hit-rate probabilities were for a “typical” image, not expected rates

formerly U18 → F24

Severity: Moderate · Area: Hit or miss page; Task 2 two-part model table

Problem. The hit-rate tables showed the chance of a hit for one imaginary, perfectly average participant looking at a perfectly average image. Participants and images differ a lot, so this “typical” value was far below the rate actually expected across everyone, and below the observed shares. It also made the differences between visualizations look larger in relative terms. Technically: emmeans(type = "response") on the binomial mixed models sets all three random intercepts to zero.

Resolution (23 Nov 2026). The tables now report the expected rate averaged over all participants, stimuli and images, as the Task 2 page already does for the expected score (F13).

  • How. A shared helper, marginal_response_by_vistype() in scripts/analysis_setup.R, integrates over the summed random-intercept variance.
  • 95% confidence intervals. From 4,000 draws of the model parameters.
  • Where it is used. The Hit or miss table (hit; hit or near hit) and the Task 2 two-part model table (probability of exact peak; mean score of misses).
  • Typical-image values are no longer shown.
  • p values are unchanged: they compare visualizations on the model scale.

Example: Basic topoplot (measured 24 Nov 2026, N = 150).

What is shown Old: typical image New: averaged Observed
Exact hit 5% [3, 11] 13% [8, 20] 14.9%
Hit or near hit 26% 35% [26, 46] 38.2%

The new values are close to the observed shares. Adjacent plots vs Basic topoplot is now 22% vs 13% (was 13% vs 5%).

F12. Task 1 text overstated weak effects

F13. Task 2 “detection score” was μ, not the expected score

formerly U6 → F13

Severity: Moderate · Area: Task 2 reporting

Problem. In Task 2 a participant’s score can be exactly 0 (completely wrong), exactly 1 (perfect), or somewhere in between. The page reported a “detection score” that was really the average of only the in-between answers. The perfect and completely wrong answers were left out. Because many answers were perfect, this made every visualization look worse than it was, like working out a class’s average grade without the students who got full marks. Technically: emmeans(type = "response") on the ordered-beta model returns μ, the mean of the continuous part, and ignores the probability of exact 0 and 1.

Resolution (18 Nov 2026). The page now reports the full expected score, E[y]. It counts all answers: perfect, completely wrong and in between.

  • Formula. E[y] = P(1) + (1 − P(0) − P(1)) μ. In words: the chance of a perfect answer, plus the in-between average weighted by how often in-between answers occur.
  • Where P(0) and P(1) come from. From the model’s two cutpoints (psi in glmmTMB). We checked that they reproduce the actual shares of 0s and 1s in the data.
  • 95% confidence intervals. We drew 4,000 random sets of model parameters, computed the score for each, and took the middle 95%.
  • Two versions. The main score is averaged over all participants, stimuli and images. A second score is for a typical participant on a typical image.
  • Where it is used. All tables, the figure and the text on the Task 2 page now use E[y].

Example: Basic topoplot, Task 2 score computed four ways (measured 24 Nov 2026, N = 150).

What is shown Score [95% CI]
Old score: average of the in-between answers only (μ) 68.4%
New score for a typical participant on a typical image (E[y], random effects set to zero) 73.3% [67.7, 78.2]
New score averaged over all participants and images (E[y]; reported on the page) 71.2% [66.0, 75.8]
Plain average of the actual answers, no model 69.8%

The old score was too low because it left out the perfect answers. The reported new score is close to the plain average of the data. The two new scores differ because the model works on a curved scale, so the score of a typical person is not the same as the average over everyone.

(The original audit quoted 67.6% for the old score. That came from an earlier model without the per-image term.)

F15. Rating models assumed proportional odds

formerly U9 → F15

Severity: Moderate · Area: Subjective-rating models

Problem. The ordinal rating models assume proportional odds: a visualization shifts every rating step (1→2, 2→3, …) by the same amount, so its effect can be summarised by one odds ratio. Tests rejected this for all four questions (p = .011 to 3 × 10⁻⁵).

Resolution (18 Nov 2026). The Subjective page has a new section, “Model checks and sensitivity analyses”.

  • The page no longer interprets odds ratios. It reports model-smoothed mean ratings instead. These differ from the raw means by at most 0.08.
  • Sensitivity. A simpler linear model (rating ~ vistype + (1 | ID)) gives the same answer for 24 of 24 contrasts: the same intervals exclude zero.

F16. Rating ranking mixed different questions and overstated a leader

formerly U10 → F16

Severity: Moderate · Area: Subjective ratings

Problem. The overall ranking summed the mean ratings of the four questions with equal weight, although they measure different things (one is likelihood of use, F10; one was asked at a different time, F11), and neighbouring ranks were indistinguishable (e.g., Uncertainty markers 12.28 [11.62, 12.88] vs Basic 12.24 [11.70, 12.82]). The tables also highlighted a “leader” per question, e.g. Confidence intervals for comparison. Resolution (18 Nov 2026).

  • The “leader” highlighting is removed. Red now marks only clear differences from Basic. A difference is clear when its Dunnett-adjusted 95% interval does not include zero. Zero means “rated the same as Basic”. In the code this flag is excludes_zero. Example: Confidence intervals for comparison has +0.18 [−0.09, 0.45]. This interval includes zero, so it is no longer red.
  • A generated list under the figure names the contrasts that exclude zero. The page states that differences among the uncertainty visualizations were not tested, so it names no “best” visualization.

F18. Fixed item order in the rating questions

formerly U13 → F18

Severity: Moderate (design limitation) · Area: Subjective ratings, manuscript

Problem. In every rating question the visualizations appear in the same order: Adjacent first, Basic always last. An item’s position affects its rating on its own (the first item sets a reference for the rest, attention drops towards the end, and the last item is seen in contrast to everything before it). Because every participant saw the same order, these position effects are mixed up with the visualizations and cannot be separated statistically. This matters most for Basic: it is the reference in every comparison and also the item most affected by being last.

Resolution (18 Nov 2026). This cannot be fixed after data collection, so it is reported:

  • a “Limitation: fixed item order” callout on the Subjective page;
  • the Task 3 description and a first paragraph in the Limitations section of journal.typ.

F21. glmmTMB was built against an older TMB

formerly U17 → F21

Severity: Low · Area: R environment, all glmmTMB models

F22. Random slopes in the rating models were not explained

formerly U9 → F22

Severity: Low · Area: Subjective-rating models

Problem. The rating model (rating_ord ~ vistype + (1 | ID)) lets participants differ only in their overall rating level. The page did not say why participant-specific preferences for visualizations (random slopes) were left out.

Resolution (18 Nov 2026). Random slopes cannot be estimated here. Each participant rated each visualization only once per item. A participant-specific effect per visualization would rest on a single rating and cannot be told apart from ordinary noise. So the model keeps only each participant’s overall level (random intercept). The “Model checks and sensitivity analyses” section on the Subjective page explains this.
